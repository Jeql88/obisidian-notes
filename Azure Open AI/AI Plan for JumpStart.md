# AI Recommended Talents Pipeline

## Summary

When a TalentRequest is created, an in-app BackgroundService generates an embedding for the job description and required skills via Azure OpenAI, then scores each candidate using a hybrid approach — vector similarity (cosine) combined with keyword skill overlap — entirely in C#. The top N candidates are inserted into the AI Recommended stage (OrderIndex 0) via TalentPipeline with a merged score stored as a match percent.

No Azure AI Search. No Service Bus. All matching logic runs inside your existing backend against embeddings stored in your existing SQL database. The only new Azure resource needed is an embedding model deployment.

**Total estimated cost: ~$1–5/month.**

Everything else — the background job, scoring logic, embedding storage — lives inside your existing app and database.

### When to add more infrastructure

|Trigger|What to add|
|---|---|
|App restarts are losing jobs mid-run|Azure Service Bus queue (~$10–11/month)|

Do not add these now. Add them only when you actually hit the problem.

## App Configuration

In your App Service → Configuration, add (pointing to Key Vault secrets, not raw values):

```
AZURE_OPENAI_ENDPOINT                → your OpenAI resource endpoint
AZURE_OPENAI_API_KEY                 → Key Vault reference
AZURE_OPENAI_EMBEDDING_DEPLOYMENT    → deployment name (e.g. "text-embedding-3-small")
RECOMMENDATION_MIN_SCORE             → e.g. 0.65 (candidates below this are excluded)
RECOMMENDATION_VECTOR_WEIGHT         → e.g. 0.7 (weight given to semantic similarity)
RECOMMENDATION_KEYWORD_WEIGHT        → e.g. 0.3 (weight given to skill keyword overlap)
RECOMMENDATION_STALE_DAYS            → e.g. 14 (days before a re-run is triggered)
```

## Database Changes

### New table — TalentProfileEmbedding

Stores the generated embedding per talent profile. Kept separate from TalentPipeline so it can be updated independently when a profile changes, without touching pipeline state.

```
TalentProfileEmbedding
- Id                  (int, PK)
- OrgProfileId        (int, FK → OrgProfile)
- EmbeddingVector     (nvarchar(max) — stored as JSON float array)
- ProfileSummaryHash  (nvarchar(64)  — SHA256 of the input text; skip re-embed if hash unchanged)
- GeneratedAt         (datetime)
- ModelVersion        (nvarchar(50)  — e.g. "text-embedding-3-small")
```

### Changes to TalentPipeline

Add recommendation metadata fields:

```
RecommendationScore      (float, nullable)        — final merged score 0–1
RecommendationPercent    (int, nullable)           — RecommendationScore * 100, shown in UI
RecommendationSource     (nvarchar(50), nullable)  — "Hybrid", "Deterministic", or "AzureOpenAI"
RecommendationVersion    (nvarchar(50), nullable)  — embedding model version used
RecommendedAt            (datetime, nullable)      — when this recommendation was inserted
MatchedSkills            (nvarchar(max), nullable) — JSON list of skills matched to the request
```

Add migration for both tables in `JumpStartVAContext.cs`.

## How Scoring Works

Each candidate gets two independent scores which are merged into one final score.

### Vector score — semantic similarity

Measures how semantically similar the talent's overall profile is to the job description. Uses the embeddings generated by Azure OpenAI.

```csharp
float vectorScore = CosineSimilarity(jobEmbedding, talentEmbedding);
// Returns 0–1. Higher = more semantically similar.
```

### Keyword score — exact skill overlap

Measures how many of the required skills the talent explicitly has. Pulled directly from TalentSkill — no embedding involved.

```csharp
float keywordScore = (float)talentSkills
    .Count(s => requestSkillIds.Contains(s.SkillId))
    / requestSkillIds.Count;
// Returns 0–1. 1.0 = has every required skill.
```

You can weight keyword score further by proficiency or years if needed later.

### Merged final score

```csharp
float finalScore = (VECTOR_WEIGHT * vectorScore) + (KEYWORD_WEIGHT * keywordScore);
// Default: (0.7 * vectorScore) + (0.3 * keywordScore)

RecommendationScore   = finalScore;
RecommendationPercent = (int)(finalScore * 100);
```

The weights are configurable via app settings. Start at 70/30 and adjust based on observed ranking quality.

### Matched skills list

A simple list of which required skills the talent actually has — stored separately from the score and shown in the UI as the human-readable reason for the recommendation.

```csharp
var matchedSkills = talentSkills
    .Where(s => requestSkillIds.Contains(s.SkillId))
    .Select(s => s.SkillName)
    .ToList();
// Stored as JSON in MatchedSkills column
```

### Cosine similarity implementation

No external library needed.

```csharp
public static float CosineSimilarity(float[] a, float[] b)
{
    float dot = 0, magA = 0, magB = 0;
    for (int i = 0; i < a.Length; i++)
    {
        dot  += a[i] * b[i];
        magA += a[i] * a[i];
        magB += b[i] * b[i];
    }
    return dot / (MathF.Sqrt(magA) * MathF.Sqrt(magB));
}
// Score of 1.0 = identical vectors, 0.0 = completely unrelated
```

A threshold of 0.65 on the final merged score is a reasonable starting point. Tune up if you're seeing weak matches; tune down if good candidates are being excluded.

## Steps

### Step 1 — Deploy embedding model in Azure OpenAI

In ai.azure.com → your US East resource → Deployments → Deploy model:

- Model: `text-embedding-3-small`
- Note the deployment name and add it to Key Vault as `AZURE_OPENAI_EMBEDDING_DEPLOYMENT`

### Step 2 — Add database tables and migrations

Create the `TalentProfileEmbedding` table and add the recommendation metadata fields to `TalentPipeline` as defined above. Run the migration.

### Step 3 — Build the embedding generation service

Create a service (`TalentEmbeddingService` or similar) that:

1. Builds a normalized profile summary string from `OrgProfile` + `TalentSkill` + resume/notes fields
2. SHA256-hashes the summary — if the hash matches what is already stored, skip the API call
3. Calls the Azure OpenAI embeddings endpoint with the summary text
4. Deserializes the returned float array and stores it in `TalentProfileEmbedding` with the hash and model version

Trigger this service on:

- OrgProfile create or update
- TalentSkill add, edit, or remove
- Nightly sweep for any profiles with no embedding or a stale model version

### Step 4 — Build the BackgroundService job

Register an in-app `BackgroundService` that processes a queue of `TalentRequestId` values held in memory (a `Channel<int>` or `ConcurrentQueue<int>` works well).

On `TalentRequest` creation in `TalentRequestLogic.cs`, enqueue the new request ID into the channel. The BackgroundService picks it up and does the following:

1. Load the TalentRequest — get required skills, job description, and derive N from required talent count or org pipeline settings
2. Generate an embedding for the job request (skills + description concatenated) via Azure OpenAI
3. Apply hard filters to the candidate pool — Approved OrgProfile, same org scope, active status, not already in any stage on this request
4. Load `TalentProfileEmbedding` records for all candidates that passed the filters
5. For each candidate, compute vector score (cosine similarity) and keyword score (skill overlap)
6. Merge into a final score using configured weights
7. Compute the matched skills list
8. Drop any candidate whose final score is below `RECOMMENDATION_MIN_SCORE`
9. Sort descending by final score and take the top N
10. Insert `TalentPipeline` rows for each with all metadata fields populated
11. If anything fails, roll back all inserts for this run — never leave the stage partially populated

### Step 5 — Update pipeline retrieval APIs

In `TalentRequestPipelineLogic.cs`, update the view models for the AI Recommended stage to surface:

- `RecommendationPercent` — displayed as a match percentage
- `MatchedSkills` — displayed as the reason for the recommendation
- `RecommendationSource` — useful for debugging ("Hybrid" vs "Deterministic")

### Step 6 — Handle stale recommendations

A scheduled sweep (can run inside the same BackgroundService on a timer) checks open TalentRequests where `RecommendedAt` is older than `RECOMMENDATION_STALE_DAYS`. For each, it clears existing stage 0 rows for that request and re-enqueues the job. This keeps the pool fresh as new talent profiles are added or updated.

## Safeguards

Enforced inside the job — not optional checks:

- Never insert a duplicate into stage 0 for the same request
- Never recommend a talent already in any later stage on the same request
- Only Approved OrgProfiles within the correct org scope enter the candidate pool
- Hard filters are applied before any scoring — the AI ranking never overrides an access or scoping rule
- Job failures roll back cleanly — no partial inserts
- Minimum score threshold prevents weak matches from padding the pool

---

## Fallback — Deterministic SQL Scoring

If the embedding pipeline is not ready or Azure OpenAI is unavailable, fall back to pure SQL scoring:

- Skill overlap between request and talent (weighted by proficiency and years)
- Recency of most recent experience
- Profile completeness

The fallback writes `RecommendationSource = "Deterministic"` so results are distinguishable from hybrid-ranked ones. The output shape — score, percent, matched skills, metadata — is identical, so the fallback can be swapped in and out without changing any downstream code.
