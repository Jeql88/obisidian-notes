# Azure AI Search

## What it is

A managed search service that lets you query data using **both text (keyword) and vector (semantic) search at the same time** — called hybrid search. Instead of choosing between exact keyword matching or meaning-based matching, you get both in a single query and the results are merged into one ranked list.

---

## Core Concepts

**Index** — the search database. You define its schema (what fields exist, what types they are, which are searchable), then push your data into it. All queries run against the index.

**Documents** — the individual records inside the index. Each document maps to one item in your data (e.g. one talent profile, one product, one article).

**Embeddings** — float arrays that represent the meaning of a piece of text. Generated by an embedding model (e.g. Azure OpenAI `text-embedding-3-small`). Stored alongside the document so vector search can run against them.

**Hybrid search** — runs a keyword search and a vector search in parallel, then merges the rankings using Reciprocal Rank Fusion (RRF) into a single result set.

**Semantic ranking** — an optional re-ranking pass on top of hybrid search results. Uses a language model to re-read the top results and reorder them based on actual meaning, not just vector proximity. Most accurate but requires Standard tier.

---

## High-Level Flow

```
Raw Data (CSV / DB)
      ↓
  Data Preparation — clean and convert to JSON
      ↓
  Embedding Generation — call OpenAI per document, attach vector
      ↓
  Index Creation — define schema in Azure AI Search
      ↓
  Add Documents — push prepared JSON + embeddings into index
      ↓
  Query Index — user sends a query, it is embedded and searched
      ↓
  (Optional) Semantic Ranking — re-rank top results by meaning
      ↓
  Return Results
```

## Step 1 — Data Preparation

Convert your raw data into JSON documents that Azure AI Search can ingest. Each row in your source data becomes one JSON object.

**Example: CSV to JSON**

A CSV row like:

```
John Doe, Software Engineer, React Expert 4yr, TypeScript Intermediate 2yr
```

Becomes a JSON document:

```json
{
  "id": "profile-001",
  "name": "John Doe",
  "title": "Software Engineer",
  "skillsSummary": "React Expert 4 years, TypeScript Intermediate 2 years",
  "profileSummary": "Software Engineer. Skills: React (Expert, 4 years), TypeScript (Intermediate, 2 years)."
}
```

The `profileSummary` field is the human-readable string you will send to the embedding model in Step 2. Keep it clean and meaningful — the quality of this string directly affects the quality of your search results.

---

## Step 2 — Generate Embeddings

For each JSON document, call the Azure OpenAI embedding model with the summary string and attach the returned vector to the document.

**Setup**

```bash
pip install python-dotenv openai
```

**.env file**

```
AZURE_OPENAI_ENDPOINT=https://your-resource.openai.azure.com/
AZURE_OPENAI_API_KEY=your-key
AZURE_OPENAI_EMBEDDING_DEPLOYMENT=text-embedding-3-small
AZURE_SEARCH_ENDPOINT=https://your-search.search.windows.net
AZURE_SEARCH_API_KEY=your-search-admin-key
```

**Embedding generation (Python)**

```python
import os, json
from dotenv import load_dotenv
from openai import AzureOpenAI

load_dotenv()

client = AzureOpenAI(
    azure_endpoint=os.getenv("AZURE_OPENAI_ENDPOINT"),
    api_key=os.getenv("AZURE_OPENAI_API_KEY"),
    api_version="2024-02-01"
)

def generate_embedding(text: str) -> list[float]:
    response = client.embeddings.create(
        input=text,
        model=os.getenv("AZURE_OPENAI_EMBEDDING_DEPLOYMENT")
    )
    return response.data[0].embedding

# Attach embedding to each document
for doc in documents:
    doc["summaryVector"] = generate_embedding(doc["profileSummary"])
```

Each document now has both its readable fields and a `summaryVector` float array ready to be pushed into the index.

## Step 3 — Define the Search Index Schema

The schema defines what fields exist in the index, what type they are, and how they behave during search and filtering.

**Field types**

|Type|Use for|Behavior|
|---|---|---|
|`SimpleField`|IDs, filters, sort keys|Stored and filterable but not full-text searchable|
|`SearchableField`|Text you want keyword-searched|Analyzed, tokenized, full-text searchable|
|`SearchField` with vector config|Embedding vectors|Vector similarity search|

**Key field** — every index must have exactly one field marked as the key. This is the unique identifier per document (like a primary key in SQL). Must be a `SimpleField` of type `Edm.String`.

**Example schema (Python)**

```python
from azure.search.documents.indexes.models import (
    SearchIndex, SimpleField, SearchableField, SearchField,
    SearchFieldDataType, VectorSearch, HnswAlgorithmConfiguration,
    VectorSearchProfile
)

fields = [
    SimpleField(name="id",            type=SearchFieldDataType.String, key=True),
    SimpleField(name="orgProfileId",  type=SearchFieldDataType.String, filterable=True),
    SimpleField(name="approvalStatus",type=SearchFieldDataType.String, filterable=True),
    SearchableField(name="title",     type=SearchFieldDataType.String),
    SearchableField(name="skillsSummary", type=SearchFieldDataType.String),
    SearchableField(name="profileSummary",type=SearchFieldDataType.String),
    SearchField(
        name="summaryVector",
        type=SearchFieldDataType.Collection(SearchFieldDataType.Single),
        searchable=True,
        vector_search_dimensions=1536,
        vector_search_profile_name="hnsw-profile"
    )
]
```

## Vector Search Algorithms

Two algorithms are available for finding nearest neighbors in vector space:

**HNSW (Hierarchical Navigable Small World)** — recommended for most cases

- Builds a graph structure that allows fast approximate nearest-neighbor search
- Very fast at query time; trades a small amount of accuracy for significant speed
- Best for large indexes where query speed matters

**KNN (K-Nearest Neighbors)** — exhaustive search

- Compares the query vector against every single vector in the index
- Perfectly accurate but slow at scale
- Only practical for small indexes or offline batch processing

For a talent search use case, **HNSW is the right choice**.

**Configuring HNSW**

```python
vector_search = VectorSearch(
    algorithms=[
        HnswAlgorithmConfiguration(name="hnsw-algo")
    ],
    profiles=[
        VectorSearchProfile(name="hnsw-profile", algorithm_configuration_name="hnsw-algo")
    ]
)
```

## Step 4 — Create the Index

```python
from azure.core.credentials import AzureKeyCredential
from azure.search.documents.indexes import SearchIndexClient

index_client = SearchIndexClient(
    endpoint=os.getenv("AZURE_SEARCH_ENDPOINT"),
    credential=AzureKeyCredential(os.getenv("AZURE_SEARCH_API_KEY"))
)

index = SearchIndex(name="talent-profiles", fields=fields, vector_search=vector_search)
index_client.create_or_update_index(index)
```

---

## Step 5 — Add Documents to the Index

Push the prepared JSON documents (with embeddings attached) into the index.

```python
from azure.search.documents import SearchClient

search_client = SearchClient(
    endpoint=os.getenv("AZURE_SEARCH_ENDPOINT"),
    index_name="talent-profiles",
    credential=AzureKeyCredential(os.getenv("AZURE_SEARCH_API_KEY"))
)

# Upload in batches — more efficient than one at a time
batch_size = 100
for i in range(0, len(documents), batch_size):
    batch = documents[i:i + batch_size]
    search_client.upload_documents(documents=batch)
```

Documents are now indexed and queryable. Re-upload a document with the same `id` to update it — Azure AI Search will overwrite it.

---

## Step 6 — Query the Index

When a user sends a query, you:

1. Embed the query text using the same embedding model
2. Run a hybrid search (keyword + vector) against the index
3. Return the ranked results

```python
def search_talents(query: str, top: int = 10):
    # Embed the query
    query_vector = generate_embedding(query)

    # Run hybrid search
    results = search_client.search(
        search_text=query,               # keyword search
        vector_queries=[{
            "kind": "vector",
            "vector": query_vector,      # vector search
            "fields": "summaryVector",
            "k": top
        }],
        filter="approvalStatus eq 'Approved'",  # hard filter applied before ranking
        top=top
    )

    return [
        {
            "id": r["id"],
            "title": r["title"],
            "score": r["@search.score"]
        }
        for r in results
    ]
```

The `@search.score` returned is the merged RRF score — higher is better. You can normalize this to a 0–100 percent for display.

## Step 7 — Summarize Results with OpenAI (Optional)

Once you have the top results back, you can send them to an OpenAI chat model to generate a plain-language summary for the user instead of just returning a raw list.

```python
from openai import AzureOpenAI

chat_client = AzureOpenAI(
    azure_endpoint=os.getenv("AZURE_OPENAI_ENDPOINT"),
    api_key=os.getenv("AZURE_OPENAI_API_KEY"),
    api_version="2024-02-01"
)

def summarize_results(query: str, results: list) -> str:
    context = "\n".join([
        f"- {r['title']} (score: {r['score']:.2f})"
        for r in results
    ])

    response = chat_client.chat.completions.create(
        model="your-chat-deployment",
        messages=[
            {"role": "system", "content": "You are a helpful assistant that summarizes talent search results."},
            {"role": "user",   "content": f"Query: {query}\n\nTop matches:\n{context}\n\nSummarize why these are good matches."}
        ]
    )

    return response.choices[0].message.content
```

## Step 8 — Semantic Ranking (Optional, Standard Tier Only)

Semantic ranking re-reads the top N results from hybrid search using a language model and reorders them based on actual meaning. It does not search the full index — it only re-ranks what hybrid search already returned.

Enable it by adding `query_type="semantic"` and a `semantic_configuration_name` to your query:

```python
results = search_client.search(
    search_text=query,
    vector_queries=[...],
    query_type="semantic",
    semantic_configuration_name="default",
    top=top
)
```

You need to define a semantic configuration on your index that tells it which fields to read for re-ranking. Results will include a `@search.reranker_score` in addition to the base score.

Only add this if hybrid search quality alone is insufficient — it adds latency and requires the Standard tier (~$250/month).

## Field Design Summary

|Field|Type|Searchable|Filterable|Purpose|
|---|---|---|---|---|
|`id`|SimpleField|No|No|Unique key|
|`orgProfileId`|SimpleField|No|Yes|Org scoping filter|
|`approvalStatus`|SimpleField|No|Yes|Approved-only filter|
|`title`|SearchableField|Yes|No|Keyword search|
|`skillsSummary`|SearchableField|Yes|No|Keyword search on skills|
|`profileSummary`|SearchableField|Yes|No|Full text search|
|`summaryVector`|SearchField (vector)|Yes (vector)|No|Semantic similarity search|

## When to use Azure AI Search vs in-code similarity

|Situation|Approach|
|---|---|
|Under ~10,000 documents|Compute cosine similarity in code against SQL-stored embeddings|
|Over ~10,000 documents or speed is a concern|Azure AI Search handles it at the index level|
|Need keyword + vector combined|Azure AI Search hybrid, or implement both scores manually in code and merge them|
|Need semantic re-ranking|Azure AI Search Standard tier only|
